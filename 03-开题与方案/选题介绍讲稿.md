# 选题介绍讲稿

**题目**：《可验证的大模型代码审计系统》
**场合**：课程选题介绍 / 中期汇报开场
**时长**：约 3 分钟（正文约 850 字）

---

## 正文讲稿

各位老师、同学好，我们组选的题目是《可验证的大模型代码审计系统》。

先说我们为什么要做这个。

静态扫描工具给你 500 条告警。现在很流行让大模型帮你过一遍，它看一眼说：其中 400 条是误报，删掉吧。

**你敢删吗？**

（停顿）

我们不敢。因为模型判断错了，真漏洞就被静默丢掉了——而且**没有任何东西会报错**。你不知道自己漏了什么。

这就是我们想解决的问题。现在代码审计的困境是：传统工具**可复现但找不准**，误报太多；大模型**找得宽但不可信**，会编造漏洞。而让大模型去过滤传统工具的误报，等于**用不可信去校正不可信**。

我们的做法，核心就一句话：

> **不看模型怎么说，看代码跑不跑得出来。**

具体说：对每一条候选告警，我们把对应的代码真的取出来，在隔离的 Docker 沙箱里**实际运行一遍**——用桩程序把危险函数拦住，塞进构造好的输入，看这个输入到底能不能到达危险函数。**跑得出来，才算漏洞。**

那跑不出来呢？

**我们不说它是误报，我们说"没验证出来"。** 这是我们方案里很关键的一点：跑不出来可能是真的没漏洞，也可能是我们的桩没写好、环境没搭对。所以结果分三类——**已确认、已排除、未确认**，其中"未确认"单独统计，不混进误报率里。现有方案大多把"验证失败"直接算成误报，等于把方法局限藏起来了。

再说"可验证"这三个字是什么意思。我们的定义是：每条确认的漏洞，都附上**能直接执行的 harness 脚本、触发用的输入、环境版本、运行命令和完整日志**。换一个人、换一台机器，拿到这些材料，能自己跑出同样的结果。这才叫可验证。

怎么证明有效？我们做**三方对照**：纯静态工具、纯大模型、我们的系统，跑同一批公开数据集。除了精确率召回率，还有个我们最看重的指标，叫**第三方复现率**——让组里没参与这条验证的人，只拿报告里的材料自己复现一遍，看成功率是多少。这一项直接检验"可验证"到底成不成立。

分工上，三个人分别负责：静态分析与代码提取、动态验证流水线（这是核心）、以及流程编排与评测。

10 月 30 号中期，我们会演示这样一幕：**大模型说这条告警是漏洞，我们的系统在沙箱里把它跑起来，捕获到危险函数真的收到了没过滤的用户输入，判定它成立——同时把可复现的材料一起交出来。**

一句话总结我们的项目：**让 AI 说的每一句话，都跑得出来。**

谢谢大家。

## 一分钟速讲版

（约 260 字）

我们的题目是《可验证的大模型代码审计系统》。

现在流行让大模型帮传统扫描工具过滤误报。但大模型说"这 400 条是误报"，你敢删吗？模型判断错了，真漏洞就被静默丢掉，而且没有任何东西会报错。

我们的做法是一句话：**不看模型怎么说，看代码跑不跑得出来。**

每条候选告警，我们都把代码取出来，在隔离沙箱里真的跑一遍——用桩程序拦住危险函数，看构造的输入能不能到达。跑得出来才算漏洞；跑不出来我们叫"未确认"，不叫误报，单独统计。

每条确认的漏洞都附上可执行的脚本、输入、环境和日志，换个人能自己跑出同样结果——这才叫可验证。

评测做三方对照，核心指标是**第三方复现率**。

谢谢。

## 老师可能会问的五个问题

| 问题 | 怎么答 |
|---|---|
| **创新点在哪？** | 不在让模型更聪明，而在**不依赖模型判断**：判定依据换成代码的执行结果；同时用确定性代码管流程，LLM 只输出建议、不掌握控制权。 |
| **和 Semgrep、CodeQL 什么关系？** | 它们是**我们的输入源和基线**，不是被替代的对象。我们做的是"对既有告警做二次验证"，属于下游环节。 |
| **跑不出来怎么办？** | 单列为「**未确认**」，不并入误报率。这是刻意的：把验证失败当成误报统计，会掩盖方法局限。 |
| **数据从哪来？** | 公开数据集（SARD 的 Python 子集作受控集、Defects4Py 作真实漏洞集），**不使用爬虫、不涉及真实业务代码**。 |
| **沙箱跑代码会不会有风险？** | mock 桩会**拦截危险调用**（数据库、系统命令、文件写入），payload 是合成输入，且全程在隔离 Docker 容器内，不针对任何真实系统。 |

## 讲的时候注意三点

1. **"你敢删吗？"之后要停顿两秒**——这是全场最抓人的一句，把风险讲清楚了，后面所有技术设计才显得有必要。
2. **"我们不说它是误报，我们说没验证出来"这句要放慢**——这是本项目最有辨识度的设计，也是和所有"用 LLM 过滤误报"方案的分界线。
3. **不要念技术细节**。Extract-Mock-Test、硬编码检测器这些点到为止，被追问再展开。选题介绍只需要让人听懂**你要解决什么问题、凭什么相信自己解决了**。
