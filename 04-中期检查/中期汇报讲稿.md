## 开场（约 20 秒）

各位老师好，我们组的题目是《可验证的大模型代码审计系统》。一句话讲这个项目在干什么：对静态扫描工具产出的每一条告警，我们把对应的代码放进隔离沙箱里**真的跑一遍**——跑得出来才算漏洞，跑不出来叫"未确认"，不叫误报。

我用半分钟交代为什么做，主体时间讲**已经做出来了什么**和**接下来五周怎么做**。

## 一、选题背景（约 50 秒，压缩版）

静态扫描工具误报率高，开发者人工复核到告警疲劳，最后干脆不看。业界流行让大模型来过滤误报，但模型判断错了怎么办？真漏洞被静默丢掉，而且全程不会有任何报错——本质是"用不可信去校正不可信"。

所以我们把判定依据换掉：**不看模型怎么说，看代码跑不跑得出来**。

对准的场景也很具体：工程现场是"手上已经有 500 条告警，要判断哪条是真的"，这是**给定告警的定向复现**，而不是"从零发现漏洞"——后者是 DARPA AIxCC 那类系统在做的事，两者是两个问题。

## 二、当前已经实现的功能（约 4 分钟）

### 1. 整条流水线已经端到端跑通

从 SAST 告警输入到最终审计报告输出，链路已经能自动走完，代码在 `06-代码/auditor/`。七个模块各自的状态如下：

| 模块 | 功能 | 状态 |
|---|---|---|
| `sast_scan` | 调用 Semgrep 并归一化告警 | ✅ 跑通 |
| `llm_discover` | LLM 候选发现（SAST 之外的第二来源） | ✅ **已接真实 DeepSeek 并实测** |
| `extract` | tree-sitter 提取 sink 函数、同文件辅助函数、被引用常量 | ✅ 跑通 |
| `mock_gen` | mock 桩生成（当前模板化） | ⚠️ 模板版可用，LLM 版待接入 |
| `harness` | 组装 harness（业务片段 + mock + payload） | ✅ 跑通 |
| `sandbox` | Docker 隔离执行 | ✅ 跑通（直连降级模式） |
| `verdict` | 模式 A 硬编码检测器 + 三分类判定 | ✅ 跑通 |
| `orchestrator` | 全流程编排、重试控制、产物落盘 | ✅ 跑通 |

### 2. 实测数据（全部落盘，可复查）

**第一，SAST 扫描。**Semgrep 1.182.1 官方容器、官方默认规则集 `p/default`。对演示的漏洞样本命中 **2 条 CWE-89 告警**；同目录下的参数化安全样本**零命中**——说明规则没有滥杀无辜。

**第二，LLM 第二候选来源（今天新增并实测）。**为解决"SAST 扫不出来的漏洞怎么办"，我们实现了 `llm_discover` 通道：不依赖任何告警，直接把函数源码交给大模型判断污点流，产出与 SAST **完全同 schema** 的候选（`L-` 前缀），下游流程零改动。真实 DeepSeek 调用实测：**4 次 API 调用、0 错误、产出 1 条候选**；安全对照样本的两个函数**都返回空**，零误报。

**第三，Extract 工具与单元测试。**单元测试 **13 项全部通过**（原有 4 项 + LLM 通道 9 项），覆盖 sink 定位、辅助函数提取、跨文件缺失标记、函数外 sink 失败处理，以及 LLM 输出的容错解析、CWE 过滤与行号收敛。

**第四，端到端动态验证。**把 SAST 的两条和 LLM 的一条**合并后统一验证**，三条全部在 Docker 隔离容器里复现成功：mock 捕获到 payload 到达 `execute` 且未参数化，判定 **TP=3、FP=0、未确认=0** —— 其中 **L-001 是 LLM 发现的候选，走完全相同的验证链路被确认为真实漏洞**。

> 有个细节值得说：LLM 报的是第 19 行（污点进入 SQL 语句那行），SAST 报的是第 20 行（`execute` 调用行）。两者都在同一函数内，Extract 都能正确定位——说明**候选不必精确指向 sink**，只要落在同一语义单元内就能被验证，这降低了对 LLM 定位精度的要求。

**第五，证据完备性。**每条结论都附 harness 脚本、触发 payload、环境快照、复现命令和完整 stdout。现场给一条命令就能复现：

```
docker run --rm -v <A-001目录>:/work -w /work python:3.12-slim python harness.py
```

另外 LLM 通道的响应已录制，可用 `--backend replay` **在无密钥情况下离线复现**同一结果——实验不依赖密钥，也不重复产生费用。

这就是我们定义的"可验证"——**换一台机器、换一个人，凭报告里附的材料能跑出同样的结论**。

### 3. 一个已经在代码里落地的关键设计

结果分**三类**：已确认（TP）、已排除（FP）、**未确认（Unconfirmed）**。

第三类是刻意设计的。跑不出来，可能是真没漏洞，也可能是我们的桩没写好、环境没搭对。所以我们不把它算进误报，单独统计占比。现有方案大多把验证失败直接计入误报，等于把方法局限藏起来了——我们不这么做。

这一条不是纸面设计，`verdict.py` 里已经实现，并且在这次的演示结果里生效（本次未确认=0，但统计口径已经跑通）。

## 三、当前实现的边界（约 1 分 25 秒，如实说明）

有三件事还没到最终形态，都写进了中期报告：

**其一，LLM 只接入了一个点位。**要说清两个点位：**候选发现**已接真实 DeepSeek 并实测通过（第二候选来源）；但 **mock 生成**仍是模板化的（针对 CWE-89／sqlite 注入类），接入点预留在 `mock_gen`。当前演示走模板 mock，**零 LLM 调用也能闭环**——LLM 是增强件，不是必需件。

**其二，SWE-ReX 执行层做了降级。**包已装好、接口正常，但我们的开发会话有沙箱策略限制，Python 子进程连不上 Docker，冒烟测试未能连通容器。按风险预案 **R2** 改为由 shell 驱动 `docker run`，功能已验证通过，隔离语义不变（隔离原语始终是容器本身）。在标准终端环境重新验证 SWE-ReX 接入，列为下一步。

**其三，演示样本是自建的。**2 条 CWE-89 样本（漏洞 + 安全对照），目的是先验证流水线本身是否工作。真实数据集接入是下一步的第一优先级。

### 2. 三件重点要做成的事

**第一，把 mock 从模板升级到 LLM 生成。**这是全系统失败率最高的环节（语法错、依赖缺失、拦截逻辑不对），也是能覆盖更多 CWE 类型的关键。同时把 mock 组装失败率做成独立观测项如实报告——不掩盖。

**第二，接入真实数据集，把三分类真正跑实。**SARD 多为单文件样本，正好匹配 Extract 只取同文件函数的设计，用作受控主评测集；Defects4Py 检验真实项目表现。漏洞样本与安全对照**成对出现**，同时度量漏报和误报两个方向。

**第三，测出第三方复现率。**让组里没参与这条验证的成员，只凭报告附带的材料独立复现一遍，统计成功率。这一项直接检验"可验证"到底成不成立，也是我们区别于"用 LLM 过滤误报"方案最硬的证据。

### 3. 风险与降级预案

已识别四类风险：mock 生成失败率、跨文件上下文缺失、依赖环境不确定、判定归因困难。降级预案分四级：

- **必保**：SAST 扫描 + Extract + Mock + 沙箱执行 + 判定（主链路）
- **可砍**：模式 B（LLM 判定）、SWE-ReX 强依赖
- **可缩**：样本量缩至 20 条；CWE 范围缩至 89／78／22 三类
- **最后手段**：如实报告"未确认"比例，以"方法论局限的实证研究"定位交付

核心链路优先保障，**项目可按期完成**。

## 老师可能追问的问题

| 问题 | 怎么答 |
|---|---|
| 大模型在系统里到底起什么作用？ | 两个位置：静态理解（输出不直接采纳）、mock 生成；判定与流程控制权都在确定性代码手里。 |
| **静态扫描扫不出来的漏洞怎么办？** | **先明确边界：本系统不负责"发现"，负责"判定"。**系统召回上界 = SAST 召回 × 验证保留率，这是刻意的设计取舍——工程现场的痛点是"500 条告警里哪条是真的"，不是"有没有漏洞"。**架构上候选来源可插拔**：多引擎并行（Semgrep + CodeQL）、自定义规则、或让大模型不依赖告警直接读代码产出候选——**验证链路对任何来源的候选都通用，判定层不用改**（注意：这是可扩展性，尚未实现，别说过头）。**评测上同时报两个口径**：分诊召回（分母＝告警数，作为主指标）与端到端召回（分母＝数据集真实漏洞数）；并单列**候选覆盖率**＝SAST 覆盖的已知漏洞数／数据集已知漏洞总数，主动说明这一项不由本系统负责。**一句话话术**："我们不负责发现 SAST 漏掉的漏洞，只负责把候选判准；要把发现也纳进来，加一个候选来源就行，验证链路是通用的。" |
| "未确认"占比高了怎么办？ | 如实报告——它反映单元 harness 对跨文件样本的局限；改善路径是收窄 CWE 范围（聚焦注入类）和有限深度的调用链扩展。 |
| 为什么不用 Joern / CodeQL 做静态证据核对？ | 权衡过：不引入程序图，消除 GB 级内存压力；代价是告警全部流入下游、LLM 调用与沙箱开销增加，这笔账是 E5 的观测对象。 |
| 沙箱里跑攻击代码，合规吗？ | mock 拦截危险 sink，不产生真实副作用；payload 是合成输入；全程隔离容器；报告里有动态执行专项合规声明。 |
| 演示样本是自己写的？ | 是——先用自建样本验证流水线本身；SARD Python 子集与 Defects4Py 的接入是下一步第一优先级，数据集匹配关系（SARD 多为单文件，Extract 只取同文件）在开题 2.6 有论证。 |
| 第三方复现率怎么测？ | 交叉验证：未参与该条验证的成员，仅凭报告附带的材料独立操作一遍，记录是否得到同一结论；操作规程在任务书 3.5。 |
| 为什么不直接用 Claude Code 这类通用 agent 过滤误报？ | 四条硬伤：①判定是自然语言推理，结论无法独立复核；②同输入不同轨迹——不可复现，也做不了严格消融，指标不稳定；③每条告警跑一次自主循环，批量场景 token 和时延不可预算；④没有"未确认"语义，判断错时真漏洞被静默丢弃。这四条正是我们的设计逐条补掉的。 |
| 你们系统和 Claude Code 这类通用 agent 是什么关系？ | 同代技术底座（轻量 agent + 隔离沙箱，mini-swe-agent/SWE-ReX 就是这个思路），区别在**控制权归属**：它让 LLM 掌控流程，我们把控制权收归确定性代码、LLM 只在两个点位出结构化建议。定位是互补不是替代：一次性看个项目用通用 agent 合适，每天几百条告警要定分诊、要能签字的证据，用我们。一句话：Claude Code 回答"这个问题怎么解决"，我们回答"这条告警是不是真的"。 |
| 隔离沙箱是怎么实现的？靠 Docker 吗？ | 就是 Docker：`docker run --rm` 一次性容器 + 最小镜像（python:3.12-slim，只有标准库）+ 白名单挂载（只进 harness 一个目录）。SWE-ReX 只是容器调度层，隔离原语始终是容器——这也是 R2 降级预案（直接 docker run）不损失隔离语义的原因；要更强边界可加 `--network none`、`--read-only`、资源上限或 gVisor。 |
| Semgrep 是大模型做的还是我们自己写的程序？ | 都不是——第三方开源静态分析引擎。我们写的是"调用与归一化"（`sast_scan.py` 封装容器调用、整理告警 JSON）；规则来自官方默认规则集 `p/default`，是人工编写的静态模式，与大模型无关；LLM 在候选发现阶段完全不参与，只在下游做静态理解和 mock 生成。 |
| 那 Semgrep 的结果是完全可复现的吗？ | 复现链三环：引擎按镜像 digest 固定 ✅、输入代码固定 ✅、规则集快照 ⚠️——`p/default` 是 registry 在线拉取，会随时间更新，是唯一松动点；把规则导出为本地文件固化后，同输入永远同结果。LLM 的不确定性则被结构性挡在下游、任何情况下不直接采纳——**确定性夹住不确定性**。 |
| 全流程有几步用到 LLM？ | 设计上 3 个点位：静态理解、mock/payload 生成、判定模式 B（可选对照）；重试闭环的"改 mock／改 payload"是点位 2 的重复调用，不是新点位。当前演示走模式 A + 模板 mock，**零 LLM 调用即闭环**——LLM 是增强件不是必需件，每告警还有调用次数预算上限。 |
| source、sink、污点传播、净化标记是什么？ | 描述"污点路径"的四个词：source 是不可信输入入口，sink 是危险操作点，传播是数据流动路径，净化标记是路上有没有被清洗。**有问题的不是某行代码，而是一条数据的走法**——同样的代码改成参数化就不构成漏洞。我们找的是污点路径；沙箱验证就是放一滴带荧光标记的水（payload），看它是否真的从未净化路径流到了 sink。 |
| 动态验证这一步，往 Docker 里输入了什么？ | 最小输入：固定 digest 的最小镜像 + 一个自包含 `harness.py`（内联业务片段、mock 桩、payload 三样）。**不进容器的**：其余源码、宿主机其他目录、网络与凭证、环境变量——输入越少越安全，也越可复现（所有输入有 sha 与快照记录）。 |
| 容器的环境是怎么确定的？ | 环境=镜像：版本是代码里的常量，真正锁死靠内容摘要 digest（如 `python:3.12-slim` 的 sha256，记入 `env_snapshot.json`），依赖只经 `requirements.txt` 或预构建镜像一条受控通道，装失败记为环境问题、归入"未确认"。第三方按 digest 重建，环境逐字节相同——这就是"可独立复现"里环境那一项的落点。 |
