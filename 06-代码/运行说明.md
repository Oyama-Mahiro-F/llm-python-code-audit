# 运行说明

> 面向 Windows 环境。命令已在本机实测（2026-11-13 验证 `prepare` 阶段）。
> 工作目录：`06-代码/`

---

## 〇、前置条件

| 项 | 要求 | 检查方式 |
|---|---|---|
| **Docker Desktop** | 必须启动（沙箱执行靠它） | `docker version` 能打出 Server 版本 |
| **Python 虚拟环境** | `06-代码/.venv`（Python 3.12.13） | `.venv\Scripts\python.exe --version` |
| **Git Bash** | 执行沙箱脚本用 | `C:\Program Files\Git\bin\bash.exe` 存在 |
| **DeepSeek API Key** | **只有真实调用 LLM 时需要** | `$env:DEEPSEEK_API_KEY` |
| **DOCKER_HOST**（可选） | 想让 Python 直接驱动 Docker（一体化模式 / SWE-ReX）时需要 | Docker Desktop 开启 `Expose daemon on tcp://localhost:2375 without TLS`，然后 `$env:DOCKER_HOST = "tcp://127.0.0.1:2375"` |

> **为什么需要 DOCKER_HOST**：Windows 下 Python 子进程访问不了 Docker 命名管道
> （实测：`docker --version` 从 Python 可跑，但任何连接守护进程的命令报
> `permission denied ... npipe://`）。改走 TCP 端点即可绕开。
> 不开也能用——只是必须走「三阶段 + Git Bash」模式。

> ⚠️ 本机的 `bash` 默认指向 `C:\Windows\System32\bash.exe`（WSL），
> **必须用 Git Bash 全路径**：`C:\Program Files\Git\bin\bash.exe`。

启动 Docker Desktop 后等托盘图标变绿再继续。

## 一、最快跑通：离线演示（约 3 分钟，不需要 API Key）

用**已有的候选告警 + 已录制的 LLM 响应**跑完整链路，只依赖 Docker。

```powershell
cd D:\university_learning\4.1\信息安全工程概论\06-代码
$PY = ".venv\Scripts\python.exe"
$RUN = "demo1"

# ① 阶段一：提取 + 生成 mock + 组装 harness（不需要 Docker）
& $PY -m auditor.orchestrator prepare `
  --alerts records/sast_alerts_multi.json records/llm_candidates_multi.json `
  --project samples --run-id $RUN --out records `
  --mock-backend replay --mock-replay-file records/mock_replay_multi/llm_replay.json `
  --verdict-mode A

# ② 阶段二：在 Docker 沙箱里执行（需要 Docker）
& "C:\Program Files\Git\bin\bash.exe" "records/run_$RUN/sandbox_cmds.sh"

# ③ 阶段三：回收执行结果 + 判定 + 出审计报告
& $PY -m auditor.orchestrator collect `
  --alerts records/sast_alerts_multi.json records/llm_candidates_multi.json `
  --project samples --run-id $RUN --out records `
  --mock-backend replay --mock-replay-file records/mock_replay_multi/llm_replay.json `
  --verdict-mode A
```

**看结果**：

```powershell
Get-Content records\audit_report.md -Encoding utf8
```

预期输出：5 条告警，`TP=5 / FP=0 / 未确认=0`，每条附复现命令。

## 一之二、一体化模式（推荐；需开启 DOCKER_HOST）

开了 TCP 端点后，Python 可以自己驱动 Docker，**一条命令**跑完 prepare + 沙箱执行 + collect：

```powershell
$env:DOCKER_HOST = "tcp://127.0.0.1:2375"   # Docker Desktop 需开启 2375
cd D:\university_learning\4.1\信息安全工程概论\06-代码

& .venv\Scripts\python.exe -m auditor.orchestrator run `
  --alerts records/sast_alerts_multi.json records/llm_candidates_multi.json `
  --project samples --run-id oneshot --out records `
  --mock-backend replay --mock-replay-file records/mock_replay_multi/llm_replay.json `
  --verdict-mode A
```

预期输出：

```
[run] A-001: verdict=TP
[run] A-002: verdict=TP
[run] L-001: verdict=TP
[run] L-002: verdict=TP
[run] L-003: verdict=TP
[orchestrator] summary: {'TP': 5, 'FP': 0, 'Unconfirmed': 0}
```

比三阶段模式省事：不用生成 `sandbox_cmds.sh`、不用 Git Bash。

## 二、完整流程：从零开始（需要 API Key）

### 1) SAST 扫描

```powershell
# 官方容器跑 Semgrep（Windows 不支持原生运行）
docker run --rm -v "$((Get-Location).Path -replace '\\','/')/samples:/src" `
  -e SEMGREP_SEND_METRICS=off semgrep/semgrep:latest `
  semgrep scan --json --config p/default /src | Out-File -Encoding utf8 records/semgrep_raw.json

# 归一化
& $PY -m auditor.sast_scan normalize --raw records/semgrep_raw.json `
  --out records/sast_alerts.json --config p/default
```

### 2) LLM 候选发现（第二来源，可跳过）

```powershell
$env:DEEPSEEK_API_KEY = "sk-..."     # 只在本次会话生效，不要写进文件

& $PY -m auditor.llm_discover --project samples --out records/llm_candidates.json `
  --backend deepseek --record-dir records/llm_replay_new
```

> 用 `--record-dir` 录下响应，下次可 `--backend replay --replay-file <文件>` 离线复现。

### 3) 动态验证（prepare → 沙箱 → collect）

```powershell
& $PY -m auditor.orchestrator prepare `
  --alerts records/sast_alerts.json records/llm_candidates.json `
  --project samples --run-id full1 --out records `
  --mock-backend deepseek `
  --verdict-mode A

& "C:\Program Files\Git\bin\bash.exe" "records/run_full1/sandbox_cmds.sh"

& $PY -m auditor.orchestrator collect `
  --alerts records/sast_alerts.json records/llm_candidates.json `
  --project samples --run-id full1 --out records `
  --mock-backend deepseek `
  --verdict-mode A
```

### 4) 重试闭环（可选）

判定结果是 FP / 未确认、且建议改 mock 时，带反馈再生成一轮：

```powershell
& $PY -m auditor.orchestrator regen `
  --alerts records/sast_alerts.json records/llm_candidates.json `
  --project samples --run-id full1 --out records --round 2 `
  --mock-backend deepseek --verdict-mode A

& "C:\Program Files\Git\bin\bash.exe" "records/run_full1/sandbox_cmds_round2.sh"

& $PY -m auditor.orchestrator collect --alerts ... --round 2 ...
```

上限 3 轮，轨迹写入 `records/run_<id>/retry_trace.jsonl`。

## 三、判定模式与后端

| 参数 | 取值 | 说明 |
|---|---|---|
| `--verdict-mode` | `A` / `B` | A = 硬编码检测器（**主判**）；B = LLM 读日志推理（带三道护栏，作复核） |
| `--mock-backend` | `template` / `deepseek` / `replay` / `dry` | mock 桩的生成方式 |
| `--judge-backend` | `deepseek` / `replay` / `dry` | 仅模式 B 使用 |

**典型组合**：

| 场景 | 参数 |
|---|---|
| 离线演示 | `--mock-backend replay --mock-replay-file ... --verdict-mode A` |
| 真实运行 | `--mock-backend deepseek --verdict-mode A` |
| 模式比选 | `--verdict-mode B --judge-backend deepseek --judge-record-dir records/judge_replay_<id>` |
| 无模板 CWE 测试 | `--mock-backend dry`（验证提示词构造，不产生 mock） |

## 五、产物在哪

| 路径 | 内容 |
|---|---|
| `records/audit_report.md` | **审计报告**（三分类结果 + 每条告警的复现命令） |
| `records/alerts_result.jsonl` | 每条告警的完整判定记录 |
| `records/run_<id>/<告警ID>/` | 单条告警全部证据：`snippet.py`、`mock_patch.py`、`payload.txt`、`harness.py`、`env_snapshot.json`、`stdout.txt`、`exit_code.txt` |
| `records/run_<id>/sandbox_cmds.sh` | 沙箱执行命令（可逐条复现） |
| `records/e2/e2_report.md` | E2 消融实验报告 |
| `records/env.json` | 运行环境快照（版本、镜像、提示词版本） |

**第三方复现**：把某个 `run_<id>/<告警ID>/` 目录拷给别人，执行

```bash
docker run --rm -v <该目录>:/work -w /work python:3.12-slim python harness.py
```

即可独立复现同一结论。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop 没启动 | 启动后等托盘变绿 |
| `permission denied ... npipe:////./pipe/dockerDesktopLinuxEngine` | Windows 命名管道权限：Python 子进程连不上守护进程 | 开 Docker Desktop 的 TCP 2375，设 `$env:DOCKER_HOST="tcp://127.0.0.1:2375"`；或改用三阶段 + Git Bash |
| 沙箱脚本报路径错误 | 用了 WSL 的 bash | 改用 `C:\Program Files\Git\bin\bash.exe` |
| 容器内 `pip install` SSL 失败 | 容器访问不了 pypi.org | 用自建镜像 `swerex-runner:1.4.0`（预装 swe-rex） |
| `no_template_for_cwe` | mock 用了 `template` 后端但该 CWE 无模板 | 换 `--mock-backend deepseek` 或 `replay` |
| LLM 调用 401/422 | 没设 API key 或 model 参数为 null | 检查 `DEEPSEEK_API_KEY`；不要显式传空 `--mock-model` |
| 大量"未确认" | harness 构造不出来（跨文件、依赖缺失） | 属预期行为，按三分类口径不计入误报 |
